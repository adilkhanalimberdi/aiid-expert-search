Ты фронтенд-инженер команды на хакатоне. Собираешь `web/` по готовому макету и подключаешь к работающему бэкенду.

## Проверка перед стартом (обязательно)

1. Посмотри `docs/design/`. Если там нет ничего, кроме `README.md` (нет PNG, PDF, HTML или описания экранов), **остановись**: напиши, что ждёшь макет в `docs/design/`, и ничего не меняй.
2. Проверь бэкенд: подними `uvicorn` (или `docker compose up`) и сделай `curl` на `/api/health` и `/api/search`. Если поиск отвечает 501 или эндпоинтов из `AGENTS.md` нет, остановись и скажи, что сначала нужно закончить `/hackathon`.
3. Прочитай `AGENTS.md` (разделы «API» и «Фронтенд»), `CONVENTIONS.md` (раздел TypeScript и React), `CLAUDE.md`, `web/src/lib/api.ts`, `web/src/index.css`.

## Окружение

Windows, твой Bash = Git Bash. `cd web && npm install`. Dev-сервер `npm run dev` (http://localhost:5173, `/api` проксируется на :8000).

## Что делать

Ветка `ui/web` по `CONVENTIONS.md`, Conventional Commits, в конце `git switch master && git merge --ff-only ui/web`. Не пушь.

1. **Макет главнее текста.** Повтори из `docs/design/` раскладку, цвета, типографику, отступы и тексты. Чего в макете нет, бери из раздела «Фронтенд» в `AGENTS.md`. Новые цвета: токеном в `src/index.css`, не HEX в JSX. Используй скилл impeccable.
2. **Экраны.**
   - «Поиск»: запрос, Enter, примеры запросов, фильтр отрасли из `/api/industries`, «Скрыть занятых», строка «как понят запрос», лучший кандидат с процентом и «Почему подходит», остальные кандидаты, кнопки отзывов, раскрывающееся «Как считается совпадение».
   - «Данные»: загрузка CSV перетаскиванием, результат загрузки (`loaded` / `skipped` / `errors`), первые строки базы.
   - «Аналитика»: `/api/stats`, результаты eval из `backend/data/eval_results.json` (скопируй сборкой или отдай через API, выбери проще).
   - Бонусы, если бэкенд их уже отдаёт (смотри раздел API в `AGENTS.md`): «Почему не он?», «Собрать команду», «Похожие эксперты», «Спрос без предложения». Показывай только то, что реально работает на бэкенде.
3. **Состояния:** загрузка (скелетоны), пустой запрос, `weak_match`, ошибка бэкенда с понятным текстом. Плашка про синтетические данные видна всегда.
4. **Адаптив:** 390 и 1280 px, на телефоне всё в одну колонку.

## Проверка

- `npm run lint` и `npm run build` зелёные.
- Playwright MCP: открыть страницу, сделать запрос из кейса и запрос с опечаткой, скриншоты на 390 и 1280 рядом с макетом, исправить расхождения. Повторить, пока не совпадает.
- `docker compose up --build`: UI на http://localhost:8080 работает так же.
- README: добавь скриншот главного экрана.

## Правила

- Контракт API не меняешь. Нужно новое поле: остановись и скажи, какое и зачем.
- Никаких UI-китов и новых тяжёлых зависимостей без согласия человека.
- Никаких сетевых запросов, кроме своего `/api` (шрифты уже локальные).
- `git push` только с разрешения.
