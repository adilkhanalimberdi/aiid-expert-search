## Окружение (Windows, твой Bash = Git Bash)

- Python только `.venv/Scripts/python.exe`. Зависимости: torch CPU (`.venv/Scripts/python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cpu`), затем `-r backend/requirements-dev.txt`. Уже стоит: не переустанавливай.
- Модель уже скачана в `backend/models/bge-m3`. В рантайме из интернета ничего не качаем. Проверь: загрузка с `HF_HUB_OFFLINE=1`, encode двух близких и двух далёких фраз, косинус близких выше. Замерь время загрузки модели и encode одного запроса на CPU.

## Этапы

Каждый этап в своей ветке по `CONVENTIONS.md`, коммиты Conventional Commits, в конце проверки зоны, затем `git switch master && git merge --ff-only <ветка>`. Не пушь.

### 1. `data/generator`

`backend/scripts/generate_data.py`, seed 42, без сети и без LLM:

- 150 экспертов. Все 5 отраслей из `industries.json` примерно поровну. Города из `cities.json`, минимум 6, Алматы и Астана чаще. Опыт 2–30 лет. availability примерно 65% `available`, 15% `partial`, 20% `busy`.
- Компетенции из реалистичных пулов по отраслям (12–20 на отрасль, у эксперта 3–6). Должности, вымышленные организации, `bio` в 1–2 предложения из шаблонов, языки.
- ФИО вымышленные, казахские и русские, из списков имён и фамилий с согласованным родом.
- Встрой ловушки под эталонные запросы: синонимы в компетенциях (испытания и исследования), двойник с тем же профилем в другом городе, сильный занятый кандидат рядом со свободным чуть слабее, аббревиатуры (GMP, ISO 9001, BIM, HSE), междисциплинарные профили (ML на производстве), эксперт под казахский запрос.
- `backend/data/experts.csv`: UTF-8 с BOM (чтобы открывался в Excel), разделитель запятая, компетенции через `;`.
- `backend/data/eval_queries.json`: 7 запросов в формате из `AGENTS.md`. Основа: `eval_queries.example.json`, id подставь реальные.
- `backend/data/eval_holdout.json`: ещё 10 запросов другими словами и про других экспертов. Это имитация запросов жюри: при настройке весов на него НЕ смотришь, только в конце этапа 2.

Проверка: повторный запуск даёт побайтово тот же CSV; CSV читается pandas; печатается сводка по отраслям, городам, статусам.

### 2. `feat/engine`

Реализуй `text`, `query_parser`, `index`, `ranker`, `explain` и `scripts/eval.py` строго по разделу «Как работает поиск» в `AGENTS.md`.

- `text`: кэш лемм (`lru_cache`), стоп-слова, синонимы-фразы (многословные группы сравнивать по последовательности лемм).
- `query_parser`: город по словарю, казахские падежи по префиксу канонической формы; отрасль по ключевым леммам; «от N лет».
- `index`: модель грузится один раз; эмбеддинги экспертов и их компетенций батчем; кэш `.npy` в `settings.cache_dir` по sha256 содержимого CSV и имени модели.
- `ranker`: режимы `hybrid` / `bm25` / `vector`, RRF, бусты, `hide_busy`, фильтр отрасли, процент, `weak_match`, debug-ранги.
- `explain`: `matched` / `related` / `reasons`, только из полей эксперта.
- `eval.py`: таблица по каждому запросу (запрос, топ-3 id и имена, попал ли, позиция нужного, мс), итог X/N, среднее и p95 времени; флаги `--mode`, `--file` (по умолчанию `eval_queries.json`), `--k`; итоги пишет в `backend/data/eval_results.json` (потом фронт покажет их на экране «Аналитика»).

Цель: `hybrid` не меньше 6/7 (лучше 7/7) на `eval_queries` и не меньше 8/10 на holdout, p95 меньше 300 мс без учёта загрузки модели. Таблицу трёх режимов на обоих наборах положи в описание коммита и в README.

Тюнинг только словарями, стоп-словами и весами в `config.py`. Подгонка под конкретные id запрещена. Holdout заметно хуже eval: это переобучение, откатывай последние правки.

Тесты pytest: `normalize`/`lemmas`, `parse` (город, казахский падеж, опыт), RRF на игрушечных данных.

### 3. `feat/api`

`main.py`: lifespan загружает CSV и строит индекс; все эндпоинты из `AGENTS.md`; `upload` пересобирает индекс без перезапуска и возвращает `loaded` / `skipped` / `errors`; битый CSV даёт 400 с понятным текстом; `feedback` и `stats` в SQLite (`settings.feedback_db`, папку создавай сам); лог запросов для дашборда.

Тесты: pytest + `TestClient` на каждый эндпоинт, включая CSV без обязательной колонки и пустой запрос. Вручную: uvicorn, `curl` на `/api/search` с запросом из кейса, время ответа.

### 4. `chore/docker`

`docker compose up --build` с нуля поднимает всё (`compose.yaml` уже есть, правь при необходимости). Фронт пока заглушка, это нормально. Проверь: health бэкенда, `curl` на `/api/search` через http://localhost:8080/api/search (то есть через nginx), загрузку CSV, время старта бэкенда (с тома Windows модель грузится медленнее, запиши цифру). Docker Desktop не запущен: спроси меня, не обходи.

### 5. `feat/<бонус>`: только бэкенд

По очереди, каждый отдельной веткой, пока есть время. Делаешь эндпоинт, логику, тесты и описание в разделе API в `AGENTS.md`. Если меняешь контракт, синхронно правишь **только типы** в `web/src/lib/api.ts`, никаких компонентов. Список могут поменять люди через аргументы команды.

1. Казахский запрос в eval зелёный.
2. «Почему не он?»: `GET /api/experts/{id}/explain?query=...` объясняет любого эксперта вне топа (каких компетенций не хватает, другой город, занят).
3. «Собрать команду»: `POST /api/team` для запроса с несколькими компетенциями, жадный подбор 2–3 экспертов, вместе покрывающих все, плюс матрица покрытия в ответе.
4. «Похожие эксперты»: `GET /api/experts/{id}/similar` по вектору.
5. «Спрос без предложения»: в `/api/stats` частые компетенции из запросов, по которым лучший результат слабый.

### 6. `docs/backend-release`

README: реальные цифры точности и скорости, таблица режимов, запуск через venv и через Docker, «Как это работает». Обнови таблицу «Решения» и раздел API в `AGENTS.md`. Прогон бэкенда с нуля по README в новом терминале с `HF_HUB_OFFLINE=1`.

Затем остановись и отчитайся. Фронт не начинай, даже если время осталось: скажи, что можно запускать `/frontend`.

## Правила

- Маленькие шаги. После каждого запускай проверки своей зоны. Красное чини сразу.
- Контракт API меняется только вместе с типами в `web/src/lib/api.ts`. Больше ничего в `web/` не трогаешь.
- Новые тяжёлые зависимости (LLM, БД, векторные базы, UI-киты) только с моего согласия.
- В рантайме никаких сетевых вызовов.
- Код должен объясняться жюри за минуту: простые функции, понятные имена, без магии.

## Когда спрашивать

Только если: нужен `git push`; нет Docker Desktop или другого доступа; решение необратимо или меняет архитектуру из `AGENTS.md`; метрика не растёт после трёх подходов к тюнингу. Остальное решай сам и записывай в таблицу «Решения».
