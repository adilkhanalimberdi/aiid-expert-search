# Sarap: подбор экспертов для AIID

Хакатон-прототип для Альянса инновационно-индустриального развития (AIID). Пользователь пишет запрос обычным языком («нужен специалист по GMP и клиническим исследованиям из Алматы»), сервис возвращает топ-3+ экспертов из CSV и объясняет, почему каждый подходит.

Сдача: 21.11.2026, 09:00 (Алматы).

## Что оценивает жюри

| Критерий | Вес |
| --- | --- |
| Точность: нужный эксперт в топ-3 на эталонных запросах (порог 4 из 5) | 30% |
| Обоснование рекомендации | 15% |
| Работа от начала до конца: жюри вводит свой запрос | 15% |
| Скорость (лимит 30 с, наша цель меньше 1 с) | 10% |
| Учёт доступности эксперта | 10% |
| Удобство интерфейса | 10% |
| Бонусные функции | 10% |

Без порога 80% или без обоснований первое место недоступно. Подбор только через выпадающие списки не засчитывается.

## Жёсткие правила для агента

1. **Офлайн.** Никаких внешних и платных API. В цепочке поиска нет LLM. Модель грузится только из `backend/models/`.
2. **Eval после каждой правки движка.** Изменил что-то в `backend/app/` (text, query_parser, index, ranker, explain, config) или в словарях: запусти `.venv\Scripts\python.exe backend\scripts\eval.py` и покажи итог. hit@3 упал: откатывай.
3. **Не подгонять под эталон.** Никаких `if expert_id == ...`, никаких захардкоженных запросов. Жюри введёт свои. Правим словари, стоп-слова, веса.
4. **Все веса и пороги только в `config.py`.**
5. **Обоснование собирается кодом** из реальных полей эксперта. Никакого сгенерированного текста.
6. **Данные синтетические.** В интерфейсе всегда плашка «Данные синтетические и не содержат реальных персональных данных».
7. Не коммитить `models/`, `.venv/`, `.env`, `*.npy`, `backend/data/feedback.db`.
8. **Git, стиль кода и имена: [CONVENTIONS.md](CONVENTIONS.md).** Ветки `<тип>/<имя>`, коммиты `<тип>(<зона>): <что сделано>`, один коммит = одна правка, коммит только после зелёных проверок своей зоны.

## Команды

Основная машина: Windows, PowerShell. Глобальный `pip.exe` сломан, поэтому всегда `python -m pip` и всегда через `.venv`.

```powershell
# один раз, из корня репозитория
python -m venv .venv
.venv\Scripts\python.exe -m pip install -U pip "huggingface_hub[cli]"
.venv\Scripts\python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cpu
.venv\Scripts\python.exe -m pip install -r backend\requirements-dev.txt
.venv\Scripts\hf.exe download BAAI/bge-m3 --local-dir backend\models\bge-m3 --exclude "onnx/*" --exclude "imgs/*"
Copy-Item .env.example .env

# бэкенд (http://localhost:8000, Swagger на /docs)
cd backend; ..\.venv\Scripts\python.exe -m uvicorn app.main:app --reload

# проверка точности
.venv\Scripts\python.exe backend\scripts\eval.py                 # гибрид
.venv\Scripts\python.exe backend\scripts\eval.py --mode bm25     # для сравнения на слайде
.venv\Scripts\python.exe backend\scripts\eval.py --mode vector

# фронт (http://localhost:5173)
cd web; npm install; npm run dev

# всё вместе в Docker (UI http://localhost:8080, API http://localhost:8000/docs)
docker compose up --build
```

Настройки читаются из `.env` в корне (шаблон `.env.example`). `.env` в git не попадает.

**Docker.** `compose.yaml`: `backend` (python:3.12-slim, torch CPU) и `web` (сборка Vite + nginx, проксирует `/api`, `/docs` на бэкенд). Модель не запекается в образ, монтируется только для чтения из `backend/models`. Кэш эмбеддингов и SQLite отзывов в томе `backend-state` (`CACHE_DIR`, `FEEDBACK_DB` переопределены в compose). Для разработки удобнее venv + `npm run dev`, Docker для проверки «с нуля», демо и деплоя.

## Стек

- Backend: Python 3.12 (`.venv`), FastAPI, sentence-transformers (`BAAI/bge-m3`, запасная `intfloat/multilingual-e5-base`), rank_bm25, pymorphy3, numpy, pandas, SQLite для отзывов.
- Frontend: Vite + React + TypeScript + Tailwind. Без внешних CDN во время работы.

## Данные

CSV в UTF-8, компетенции через `;`.

| Колонка | Обязательна | Пример |
| --- | --- | --- |
| `id` | да | E001 |
| `full_name` | да | Айгерим Сатпаева |
| `position` | да | Руководитель отдела качества |
| `industry` | да | Фармацевтика |
| `competencies` | да | GMP; валидация процессов; клинические исследования |
| `city` | да | Алматы |
| `experience_years` | да | 12 |
| `availability` | да | `available` / `partial` / `busy` |
| `organization`, `bio`, `languages`, `email` | нет | |

Заголовки-синонимы маппятся автоматически («ФИО» → `full_name`, «Город» → `city`, «Статус» → `availability`). Нет обязательной колонки: ошибка 400 со списком недостающих. Битые строки пропускаются и считаются в ответе.

`eval_queries.json`: `[{"query": "...", "relevant": ["E001", "E047"]}]`. Запрос засчитан, если хотя бы один из `relevant` в топ-3. Пример с ловушками: `eval_queries.example.json`.

## Как работает поиск

**При загрузке CSV**

1. Текст эксперта: `"{position}. Компетенции: {competencies}. Отрасль: {industry}. {bio}"`. Город сюда НЕ входит, он отдельный буст.
2. Нормализация: нижний регистр, ё → е, пунктуация кроме дефиса убирается. Латинские аббревиатуры (GMP, ISO, BIM) остаются.
3. Лемматизация `pymorphy3` + стоп-слова из `stopwords.txt`.
4. `BM25Okapi` по леммам.
5. Нормализованные эмбеддинги: текст эксперта целиком и каждая компетенция отдельно. Кэш в `.npy` по хэшу CSV.

**На каждый запрос**

1. Разбор: город и отрасль по словарям (сравниваем леммы; для казахских падежей «Алматыдан», «Астанада» допускается совпадение по префиксу канонической формы). Опыт regex-ом («от 10 лет»). Остальное: ключевые термины.
2. Термины расширяются синонимами из `synonyms.json` и словами базы: по приставке («кибер» → «кибербезопасность») или с опечаткой (`difflib`). Только для BM25. Слова вне словаря pymorphy («деплой») остаются как есть.
3. BM25 по терминам: топ-30.
4. Вектор всего запроса (нижний регистр, плюс до 8 синонимов терминов), косинус (скалярное произведение): топ-30. Регистр и язык запроса не должны менять результат.
5. RRF: `score = Σ 1 / (60 + rank)` по двум спискам.
6. Бусты (множители, всё в `config.py`):

| Условие | Множитель |
| --- | --- |
| город совпал | ×1,3 |
| город указан и не совпал | ×0,8 (не исключаем) |
| отрасль совпала | ×1,2 |
| опыт ниже запрошенного | ×0,85 |
| `partial` | ×0,85 |
| `busy` | ×0,7 |
| отзывы по похожим запросам | ×(1 + 0,1 × взвешенные (лайки − дизлайки)), в пределах 0,7–1,3 |

7. Фильтр отрасли из UI жёсткий.
8. Процент: `100 × (0,6 × смысл + 0,4 × покрытие)`. Смысл = косинус, растянутый с 0,3–0,8 на 0–1. Покрытие = доля ключевых терминов, найденных у эксперта: точно (слова, синонимы) или по смыслу (косинус термина с компетенциями и должностью эксперта: от 0,66 частичный зачёт, от 0,80 полный). Затем бусты города и отрасли, потолок 99.
9. Обоснование: `matched` (точные совпадения лемм и синонимов в компетенциях), `related` (компетенции с косинусом к запросу от 0,6), плюс отрасль, город, опыт, статус.
10. Лучший косинус ниже 0,35: `weak_match: true`, UI показывает «Точных совпадений нет, вот ближайшие».

Числа стартовые. Меняем только по выводу `eval.py`.

## API

Контракт в `backend/app/schemas.py`. Типы синхронизированы с `web/src/lib/api.ts`.

`/api/stats` также возвращает `evaluations`: сохранённые метрики по наборам и режимам.
Загрузка принимает до 10 МБ UTF-8 CSV, возвращает `loaded`, `skipped`, `errors`; невалидный файл не заменяет индекс.
Загруженный CSV хранится отдельно (`UPLOADED_CSV`), исходный демонстрационный каталог не изменяется.

| Метод | Путь | Что делает |
| --- | --- | --- |
| POST | `/api/search` | поиск, главный эндпоинт; `lang: "ru" \| "en"` задаёт язык `reasons` (по умолчанию `ru`) |
| POST | `/api/team` | `{query, industry?, hide_busy?, max_members?: 2–3}` → участники, матрица подтверждённых терминов, `uncovered_terms`, `complete`; при нехватке подходящих профилей команда может быть меньше |
| POST | `/api/upload` | CSV (multipart), пересборка индекса без перезапуска |
| GET | `/api/experts?offset=0&limit=20` | постраничный каталог `{total, offset, items}`; limit 1–100 |
| GET | `/api/experts/{id}` | полная карточка |
| GET | `/api/experts/{id}/explain?query=...&lang=ru` | совпадения, `missing_terms` (не подтверждены компетенциями профиля), ограничения города, отрасли, опыта и доступности |
| GET | `/api/experts/{id}/similar?limit=5` | ближайшие профили по косинусу векторов, без исходного эксперта; limit 1–20 |
| GET | `/api/industries` | отрасли для фильтра |
| POST | `/api/feedback` | `{query, expert_id, verdict: "fit" | "not_fit"}` |
| GET | `/api/stats` | топ-5 компетенций, `unmet_demand` (топ-5 терминов из запросов со `weak_match`), число запросов, среднее время, доля «подошёл» |
| GET | `/api/health` | число экспертов, имя модели |

Структура главного экрана: кобальтовая шапка (бренд, разделы по центру, переключатель EN/RU/KK) с крупным заголовком, полем запроса, лаймовой кнопкой по центру, примерами и фильтрами; лаймовая плашка про синтетические данные; ниже запрос, прочитанный движком, как предложение с подсветкой (навык, город и отрасль, условия); чёрная панель лучшего кандидата с цифрой оценки, шкалой 0–100 (пороги 40 и 70) и блоком «Почему подходит»; пара «Тоже подходят» в общей рамке; линованный список «Другие кандидаты»; формула совпадения крупной типографикой.

Обязательные состояния: загрузка (скелетоны с лаймовым бликом, завитушки логотипа дорисовываются), пустой запрос, слабое совпадение, бэкенд недоступен. На телефоне всё в одну колонку.

Язык интерфейса: EN, RU, KK, переключатель в шапке, выбор хранится в `localStorage` (`sarap.lang`), по умолчанию английский. Тексты в `web/src/lib/i18n.ts`: три словаря одного типа `Dict`, компилятор требует один и тот же набор ключей. Запросы принимаются на любом из трёх языков. Обоснования (`reasons`, `constraints`) сервер отдаёт на языке из поля `lang` (`ru`, `en`, `kk`; по умолчанию `ru`), фронт шлёт язык интерфейса и перезапрашивает поиск при смене языка. Данные CSV (имена, должности, компетенции) не переводятся. Числа формулы на экране (`web/src/lib/weights.ts`) дублируют `config.py`: меняешь там, меняй и здесь.

## Решения

| Решение | Почему |
| --- | --- |
| Кейс AIID из пяти | метрику проверяем сами, стек знакомый, награда полезна для трудоустройства |
| Гибрид BM25 + эмбеддинги, без LLM | офлайн по условию, ответ меньше секунды, обоснования не выдумываются |
| `bge-m3` | многоязычная, понимает казахский; e5-base как запасная |
| RRF вместо суммы скоров | шкалы BM25 и косинуса несравнимы, RRF смотрит только на места |
| Город не в тексте эмбеддингов | иначе город перевешивает смысл; отдельный буст управляемее |
| Процент не из RRF | RRF непонятен человеку; формула «смысл + покрытие» объяснима на защите |
| Индекс в памяти, без БД | 150 записей; для 10 000 переезд в PostgreSQL + pgvector |
| Отзывы в SQLite | один файл, без сервера |
| Настройки через pydantic-settings из `.env` | путь к модели и префиксы меняются без правки кода |
| Без PostgreSQL/pgvector | 150 векторов по 1024 числа: ~0,6 МБ в памяти, сравнение одним `numpy`-умножением за доли миллисекунды. База добавит настройку и точку отказа на демо, а баллов не даст |
| Docker Compose для запуска и деплоя, модель томом | одна команда поднимает всё; образ без 2,3 ГБ модели собирается быстро; на сервере нужно ≥4 ГБ RAM |
| Векторы в памяти + кэш `.npy` | считаются один раз при загрузке CSV, при перезапуске читаются с диска за миллисекунды |

| BM25 участвует в RRF только при положительном скоре | Нулевое совпадение не является свидетельством релевантности; фильтры применяются до отбора кандидатов |

| Атомарная замена индекса и отдельный uploaded.csv | Ошибка CSV сохраняет рабочий каталог; принятая загрузка переживает перезапуск, исходные данные остаются воспроизводимыми |
| `weak_match` по доказательствам, а не по косинусу | косинус bge-m3 у посторонних запросов 0,4–0,5 против 0,5–0,7 у нормальных, один порог их не разделяет. Слабо, если ни один найденный не подтверждает термины и лучшая компетенция ниже 0,6: 10/10 посторонних запросов слабые, 0 ложных срабатываний на нормальных |
| Аббревиатуры (ИИ, ML, GMP) не лемматизируются | pymorphy превращал «ИИ» в «ия» и ломал разбор запроса |
| Эталон по правилу, а не по id (`eval_jury`) | после разнообразия данных появились другие настоящие совпадения; считаем релевантным каждого, у кого есть нужная компетенция |
| Версии зависимостей закреплены | пересборка Docker не должна менять поведение накануне демо |
| Название Sarap (было Lodestar, раньше «Компас») | от «сарапшы», эксперт: короткое, читается на трёх языках; решение команды при ребрендинге. Компас убран из знака полностью |
| Интерфейс на трёх языках (EN, RU, KK), обоснования с сервера на языке интерфейса (`lang`: ru, en, kk) | было «интерфейс на английском»; жюри в Казахстане, казахский входит в условия задачи. Тексты в трёх словарях одного типа, данные CSV не переводятся |
| Английские синонимы и стоп-слова в словарях | при английском интерфейсе жюри пишет запросы по-английски, а компетенции в базе русские |
| Оценка крупной лёгкой цифрой со шкалой 0–100 и порогами 40 и 70, без кольца; цвет по силе совпадения | 26% не должно выглядеть как успех: от 70 кобальт (лайм на тёмном), от 40 янтарный, ниже серый; шкала с порогами показывает, откуда цвет |
