# Деплой Lodestar на сервер

Каждый merge в `master` собирает образы, кладёт их в GitHub Container Registry и перезапускает сервис на вашем сервере. Проверять можно с телефона по адресу сервера.

## Сколько нужно памяти

Замеры на этой машине (CPU, `BAAI/bge-m3`, 150 экспертов):

| Что | Значение |
| --- | --- |
| Файл модели на диске | 2,2 ГБ |
| Бэкенд в покое после старта | около 1,4 ГБ RAM |
| Пик бэкенда (загрузка модели, построение индекса) | около 2,0 ГБ RAM |
| Контейнер `web` (nginx) | десятки МБ |
| Время холодного старта | около 60 секунд |
| Запрос | 150–250 мс |

Что это значит для сервера:

| RAM сервера | Вердикт |
| --- | --- |
| 4 ГБ и больше | комфортно, `mem_limit` 3 ГБ по умолчанию подходит |
| 3 ГБ | работает, если больше на сервере почти ничего нет; добавьте swap 2 ГБ |
| 2 ГБ | модель не влезет без swap и будет тормозить; нужен вариант ниже |
| 1 ГБ | не подойдёт |

Свободную память смотрите командой `free -h` (колонка `available`). Диска нужно минимум 6 ГБ: образ бэкенда около 1,5 ГБ, модель 2,2 ГБ, остальное на слои Docker.

### Если памяти мало

1. **Swap.** Самый дешёвый вариант: `fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile`. Пик при старте переживёт; в работе модель почти не выходит за 1,4 ГБ.
2. **Меньшая модель.** `intfloat/multilingual-e5-base` занимает около 1,1 ГБ на диске и заметно меньше в памяти, `multilingual-e5-small` около 0,5 ГБ. Для e5 нужны префиксы `QUERY_PREFIX=query: ` и `PASSAGE_PREFIX=passage: ` в `.env`, а точность надо перемерить `eval.py --all` на всех наборах. Скачивание и замер нужно делать осознанно: на bge-m3 сейчас 7/7, 10/10, 14/15, 12/12.
3. **Квантизация (ONNX int8)** уменьшила бы bge-m3 до примерно 0,6 ГБ, но добавляет зависимости (`optimum`, `onnxruntime`) и отдельную проверку точности. Делать, только если первые два варианта не подошли.

## Разовая подготовка сервера

Нужны Docker и Docker Compose. Под обычным пользователем (не root):

```bash
sudo mkdir -p /opt/lodestar/models && sudo chown -R "$USER" /opt/lodestar
cd /opt/lodestar

# модель скачивается один раз (в рантайме интернет не нужен)
python3 -m venv .hf && .hf/bin/pip install -U "huggingface_hub[cli]"
.hf/bin/hf download BAAI/bge-m3 --local-dir models/bge-m3 --exclude "onnx/*" --exclude "imgs/*"
```

Вместо скачивания на сервере можно один раз скопировать готовую папку: `scp -r backend/models/bge-m3 user@server:/opt/lodestar/models/`.

Порт `8080` (или свой `WEB_PORT`) должен быть открыт в файрволе. Если на сервере уже занят этот порт, задайте другой в переменной репозитория `WEB_PORT`.

## Настройка GitHub (один раз)

Создайте отдельный SSH-ключ только для деплоя, не свой личный:

```bash
ssh-keygen -t ed25519 -f lodestar_deploy -C "lodestar-deploy" -N ""
ssh-copy-id -i lodestar_deploy.pub user@server   # или добавьте .pub в ~/.ssh/authorized_keys на сервере
```

В репозитории, Settings → Secrets and variables → Actions:

| Тип | Имя | Значение |
| --- | --- | --- |
| Secret | `DEPLOY_HOST` | адрес сервера |
| Secret | `DEPLOY_USER` | пользователь на сервере |
| Secret | `DEPLOY_SSH_KEY` | содержимое приватного файла `lodestar_deploy` |
| Variable | `DEPLOY_ENABLED` | `true` (пока не задана, деплой не запускается) |
| Variable | `DEPLOY_PATH` | необязательно, по умолчанию `/opt/lodestar` |
| Variable | `WEB_PORT` | необязательно, по умолчанию `8080` |

Приватный ключ и секреты в репозиторий не коммитьте. После настройки удалите локальные файлы `lodestar_deploy*`.

## Как это работает

1. `ci.yml` на каждом PR и пуше: линтер, формат, тесты без модели, проверка, что генератор данных не дрейфует, линт и сборка фронта.
2. `deploy.yml` на push в `master` (или вручную: Actions → Deploy → Run workflow): собирает образы `backend` и `web`, кладёт в `ghcr.io/<владелец>/lodestar-*`, копирует `compose.prod.yaml` на сервер, делает `docker compose pull && up -d` и ждёт `/api/health` до 5 минут.
3. Данные не теряются: кэш эмбеддингов, база отзывов и загруженный CSV лежат в томе `backend-state`.

Адрес для проверки с телефона: `http://<адрес сервера>:8080`.

## Откат

```bash
cd /opt/lodestar
IMAGE_PREFIX=ghcr.io/<владелец>/lodestar TAG=<sha предыдущего коммита> docker compose -f compose.prod.yaml up -d
```

Образы с тегом коммита хранятся в GHCR.

## Что учесть

- **Доступа без пароля нет.** Это демо с синтетическими данными. Если сервис открыт в интернете, закройте его по IP или поставьте базовую авторизацию в nginx перед показом жюри.
- **HTTPS.** Для адреса с замком нужен домен и обратный прокси (Caddy или nginx с Let's Encrypt). Для проверки с телефона достаточно `http`.
- **Холодный старт** занимает около минуты: после деплоя первые 60 секунд сервис может отвечать 502.
- Если репозиторий приватный, образы в GHCR тоже приватные. Деплой логинится на сервере временным токеном задачи, постоянный токен там не хранится.
