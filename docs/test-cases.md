# Тест-кейсы Sarap

Документ для проверки перед сдачей и для агента, который будет проверять и чинить. Правила проекта в [AGENTS.md](../AGENTS.md): после правки движка или словарей запускать `eval.py` (hit@3 не должен упасть), не подгонять под эталон, веса только в `config.py`, коммиты по [CONVENTIONS.md](../CONVENTIONS.md).

Статус на 20.11.2026 (ветка `fix/city-false-positives`, macOS, CPU): все автоматические кейсы проходят, кроме известных недоработок K02–K03 (K01 исправлена).

## Как запускать

```bash
# 1. автотесты бэкенда (с моделью; без неё работают только test_engine и test_generator, как в CI)
cd backend && ../.venv/bin/pytest -q                    # Windows: ..\.venv\Scripts\pytest.exe -q

# 2. точность на эталонных наборах (hybrid должен дать 7/7, 10/10, 14/15, 12/12)
.venv/bin/python backend/scripts/eval.py --all

# 3. API-кейсы на запущенном сервере (не меняют каталог и отзывы)
cd backend && ../.venv/bin/python -m uvicorn app.main:app --port 8000   # в отдельном терминале
.venv/bin/python backend/scripts/check_cases.py                         # --url http://localhost:8080 для Docker

# 4. фронт
cd web && npx tsc -b && npm run lint && npm run build
```

`eval.py` перезаписывает `backend/data/eval_results.json`. Без `--all` в файле останется только один набор: верните файл через `git checkout` или перезапустите с `--all`.

## 5. Производительность и память (замер 20.11, Apple M, 4 потока CPU)

| ID | Что | Было | Сейчас | Цель |
| --- | --- | --- | --- | --- |
| P01 | Старт до `/api/health` (векторы в кэше `.npy`) | 6 с | 6 с | меньше 30 с |
| P02 | Первый поиск после старта | 292 мс | 118 мс | меньше 200 мс |
| P03 | Поиск, медиана | 60–70 мс | 60–70 мс | меньше 300 мс |
| P04 | Подбор команды, 5000 экспертов | 230–420 мс | 87–117 мс | меньше 300 мс |
| P05 | Память процесса | ~2,1 ГБ | ~2,1 ГБ | на сервере от 4 ГБ |

Почему первый поиск был медленным: внутри него модель вызывалась отдельно для каждого прошлого запроса из отзывов (2 запроса = 3 вызова по ~50–100 мс), и это росло с каждым голосом. Теперь эти запросы кодируются одним батчем при старте, при новом голосе и после загрузки CSV. Остаток (~50 мс сверху) это кодирование новых слов запроса, которые модель ещё не видела.

Масштаб (синтетические каталоги):

| Экспертов | Построение индекса (кодирование) | Из кэша `.npy` | BM25 в памяти | Векторы в памяти | Поиск, медиана |
| --- | --- | --- | --- | --- | --- |
| 150 | ~5 с (оценка) | 0,00 с | 0,1 МБ | 7 МБ | 62 мс |
| 1 000 | 53 с | 0,03 с | 0,7 МБ | 47 МБ | 54 мс |
| 5 000 | 254 с | 0,15 с | 3,5 МБ | 235 МБ | 66 мс |

Выводы: BM25 почти ничего не весит; 2 ГБ занимает модель bge-m3, и это не зависит от числа экспертов. Поиск не замедляется с ростом каталога. Узкое место только одно: кодирование при загрузке нового CSV (~30 профилей в секунду), оно идёт внутри HTTP-запроса.

## 6. Известные недоработки и задачи

| ID | Что не так | Предложение | Приоритет |
| --- | --- | --- | --- |
| K02 | Отрицание не понимается: «не нужен GMP, нужен BIM» ищет и GMP | минимум: «не» в стоп-слова; лучше: термины после «не нужен», «без», «кроме», «not», «except» исключать | низкий |
| K03 | «busy», «available» в английском запросе становятся терминами | слова доступности на английском и казахском разобрать как `available_only` или стоп-слова | низкий |
| K04 | Загрузка CSV синхронная: 1000 строк ~53 с, 5000 ~4 мин; в Docker nginx ждёт 120 с, дальше 504 | асинхронная пересборка: 202 и `job_id`, `GET /api/upload/status` с прогрессом, старый индекс работает до замены, на экране «Данные» полоса прогресса; контракт менять вместе в `schemas.py` и `api.ts` | высокий, если жюри даст CSV от 1500 строк |
| K05 | `target_matrix` дублирует векторы компетенций у каждого эксперта (5000 экспертов: 108 из 235 МБ) | хранить уникальные компетенции один раз и индексы по экспертам; нужно от 5–10 тыс. экспертов | низкий |
| K06 | Чисто векторный режим на `eval_queries` 6/7 (гибрид 7/7) | только для слайда сравнения режимов | низкий |
| K07 | Промах гибрида на `eval_jury`: «проектирование электрических сетей для завода», нужный эксперт занят (×0,7) | так задумано (учёт доступности), объяснить на защите | нет |
| K08 | Казахские тексты интерфейса и обоснований переведены без носителя | проверить носителем языка | средний |
| K09 | int8-квантизация модели проверена и отклонена: на ARM в 2,7 раза медленнее, меняет лидера выдачи в 3 из 6 запросов | не возвращаться без замера на x86 и полного eval | нет |
